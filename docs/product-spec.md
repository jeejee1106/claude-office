# Claude Office 기획서

> 이 문서는 "무엇을 보여 줄 것인가"의 기준이다. 기술 문서(이벤트 계약, 매핑 표)는 이 문서를 구현하기 위한 것이며, 둘이 충돌하면 이 문서가 우선한다.
> 표의 **출처** 열: `요청` = 사용자가 직접 원한 것, `제안` = 아직 확정되지 않은 아이디어(사용자 검토 필요). 2026-10-21 초안의 제안 항목은 사용자가 모두 확정해 `요청`으로 바꿨다, `현재` = 지금 구현된 동작. `요청→현재` = 요청으로 확정된 뒤 구현된 것(2026-10-21 3차).

## 1. 한 줄 목표

터미널에서 일하는 Claude Code를 **작은 픽셀 회사의 직원들**로 보여 준다. 화면을 흘끗 보기만 해도 "지금 뭘 하고 있는지, 막혔는지, 끝났는지"를 알 수 있어야 하고, 보는 재미가 있어야 한다.

## 3. 공간 구성

한 화면 안에 방 여러 개가 있는 작은 사무실 층. 도구 종류마다 가는 방이 달라서, 캐릭터 위치만 봐도 무슨 일을 하는지 알 수 있게 한다.

| 공간 | 들어 있는 것 | 언제 가는가 | 출처 |
| --- | --- | --- | --- |
| **서버실** | 서버랙 여러 대, 깜빡이는 LED, 모니터, 케이블 | 명령 실행(Bash) | 요청→현재 |
| 업무 공간 | 직원별 책상과 모니터 | 코드 수정·작성(Edit, Write) | 현재 |
| 자료실 | 책장, 서류 캐비닛 | 파일 읽기(Read), 검색(Grep, Glob) | 요청→현재 (파쇄기도 여기) |
| 회의실 | 화이트보드 | 계획(TodoWrite 등) | 요청→현재 (회의 테이블 = 책상이 모자랄 때 공용 자리) |
| 휴게실 | 커피머신, 소파 | 한 턴이 끝났을 때, 오래 쉴 때 | 요청→현재 (한 턴 끝). "오래 쉴 때"는 5절 "오래 쉼 = 책상에서 졺"(현재)과 겹쳐 책상 쪽을 유지 — 사용자 확인 필요 |
| 창가 | 지구본 | 웹 검색·조회 | 현재 |
| 출입문 / 로비 | 문 | 출근, 퇴근, 서브에이전트 입·퇴장 | 현재 |

> 현재 구현: 24×14 타일 층. 가운데 업무 공간(창가·로비·출입문 포함), 왼쪽 위 자료실·왼쪽 아래 휴게실, 오른쪽 위 서버실·오른쪽 아래 회의실. 방은 칸막이 벽으로 나뉘고 벽의 출입구로만 오간다.

## 6. 대사 규칙

- 말풍선은 한 사람당 하나. 새 말풍선이 뜨면 이전 것은 바로 사라진다(정보가 늦게 보이지 않게).
- 같은 상황에 대사 후보를 여러 개 둬서 단조롭지 않게 한다. 어떤 후보를 쓸지는 이벤트 ID로 정해서, 리플레이할 때마다 같게 나온다.
- 도구 말풍선(파일명, 명령)이 대사보다 우선이다. 대사는 도구 사용이 없는 순간에만 짧게(1~2초) 띄운다.

> 6절 규칙: 요청→현재. 대사는 1.5초. 대사를 띄우는 제자리 행동(멈칫 등)은 다음 도구가 오면 최소 0.6초 뒤 끊기고 도구 말풍선으로 바뀐다. 퇴장 대사는 사라질 때까지 유지(최대 2초). 후보는 상황마다 3개(한/영), 이벤트 ID 해시로 고른다.

## 8. 아직 정하지 않은 것 (사용자 의견 필요)

- 여러 세션(Claude Code 창 여러 개)을 동시에 보여 줄 때: 층을 나눌지, 한 사무실에 섞을지, 하나만 고르게 할지
- 효과음 여부
- 사무실 꾸미기(테마, 계절 장식 등) 여부
- 하루 작업량 통계(오늘 수정한 파일 수 등)를 보여 줄지

## 9. 범위 밖
